# EMS 售前调研工具用户手册（代码同步版）

更新时间：2026-05-09
适用版本：当前 `master` 分支实现

## 1. 文档说明

本手册面向系统管理员、售前工程师、外部客户用户，按“功能用例”说明实际可操作流程。每个用例均包含：
- 操作步骤：用户在页面上怎么做。
- 业务流程：系统在后台如何处理、数据如何变化。

## 2. 角色与访问范围

### 2.1 内部用户
可访问全部模块：
- 售前综合看板
- 客户调研管理（调研列表、模板、创建、填写、报告）
- 产品方案管理（产品能力、报告模板）
- 系统设置（用户、角色、字典、售前配置、消息、日志）

### 2.2 外部用户
仅允许访问：
- `/customer-survey/list`
- `/surveys/fill/:id`
- `/authorized/surveys/fill/:id`

若外部用户进入其他路径，系统会自动重定向到调研列表。

## 3. 端到端业务主流程

### 3.1 内部售前流程
1. 登录系统。
2. 在“调研表单列表”新建调研，选择模板和售前负责人。
3. 进入填写页完善问卷，系统自动保存草稿。
4. 点击“提交并生成报告”，系统生成 AI 报告和模板报告。
5. 在报告详情页查看结果、分享链接、导出 PDF。

### 3.2 外部客户流程
1. 通过授权链接进入填写页（未登录会先去登录页）。
2. 可注册外部账号后继续填写。
3. 提交后调研状态变更为“已完成”，报告在内部可查看。

## 4. 功能用例（操作步骤 + 业务流程）

### UC-01 登录

操作步骤：
1. 打开 `/login`。
2. 输入用户名、密码，点击“登录”。
3. 登录成功后跳转到首页或 `redirect` 参数指定页面。

业务流程：
1. 前端调用 `authService.login`。
2. 服务层读取 `users` 表匹配用户名，校验密码摘要；历史明文记录登录后需逐步迁移。
3. 登录成功后写入本地 `ems_user`、`ems_token`，并更新用户 `last_login_time`。
4. 系统向 `system_logs` 写入登录成功或失败日志，失败日志只记录账号标识和错误原因，不记录密码。
5. 若启用了自动外部创建（授权链接场景），不存在用户时会自动创建外部账号。

### UC-02 外部用户注册

操作步骤：
1. 打开 `/register`。
2. 输入姓名、用户名、手机号、邮箱、密码与确认密码。
3. 提交成功后自动登录。

业务流程：
1. 前端调用 `authService.register`。
2. 系统校验必填项与用户名唯一性。
3. 使用“外部客户”角色创建用户（`users` 表），状态默认 `enabled`。
4. 注册成功后写入 `ems_user`、`ems_token`。
5. 系统记录注册并登录成功日志；注册失败时记录失败原因。

### UC-03 新建调研（直接创建）

操作步骤：
1. 进入“客户调研管理 > 调研表单列表”。
2. 点击“新建表单”进入 `/surveys/new`。
3. 选择“当前页面直接创建”，填写表单名称、客户、项目、行业、区域、售前负责人、调研模板。
4. 点击“创建并提交”，系统跳转到填写页。

业务流程：
1. 页面加载时拉取角色和用户，只显示“售前工程师”可选负责人。
2. 提交时写入 `survey_forms`：
   - `status=draft`
   - `report_status=pending`
   - `creator_id/submitter_id/pre_sales_responsible_id`
   - `data` 里写模板初始化字段。
3. 成功后缓存 `ems_last_created_survey_id` 并跳转 `/surveys/fill/:id`。

### UC-04 新建调研（生成外部填写链接）

操作步骤：
1. 在新建调研页选择“生成外部填写链接”。
2. 填写同 UC-03。
3. 点击“创建并提交并生成链接”。
4. 页面展示授权 URL，可复制或新开页面。

业务流程：
1. 创建调研时在 `data.external_link_enabled=true`。
2. 链接格式：`#/authorized/surveys/fill/{surveyId}`。
3. 外部用户首次访问时，会把用户 ID 加入 `data.external_access_user_ids`。

### UC-05 调研列表管理

操作步骤：
1. 进入 `/customer-survey/list`。
2. 可按关键字搜索（表单名/项目/客户）。
3. 可按状态筛选（草稿/填写中/已完成）。
4. 可按创建时间或提交时间升降序排序。
5. 可执行：
   - 点击名称进入填写页。
   - 点击“查看报告”进入报告页（仅已生成）。
   - 点击“重填”（已完成表单）。
   - 点击“删除”。

业务流程：
1. 调用 `surveyService.getSurveys` 拉取列表；外部用户仅返回授权范围内记录。
2. “重填”会更新：`status=draft`、`report_status=pending`，清空提交时间展示。
3. “删除”调用 `surveyService.deleteSurvey`，删除 `survey_forms` 记录。

### UC-06 调研填写与草稿保存

操作步骤：
1. 打开 `/surveys/fill/:id` 或授权地址。
2. 页面顶部显示统一详情头部，展示表单名称、客户、项目、行业、区域和当前状态。
3. 按模板填写字段（文本、数字、单选、多选、文本域）。
4. 点击“保存草稿”可手动保存。
5. 页面默认开启自动保存（延迟约 1200ms），保存状态会在顶部提示区展示。
6. 点击“返回列表”前会自动尝试保存。
7. 已生成报告的表单，可通过顶部“表单 / 报告”页签直接切换到报告页。

业务流程：
1. 页面先加载调研详情；授权路径会触发授权绑定逻辑。
2. 字段变更后状态进入“填写中”，写入 `form.data`。
3. 手动或自动保存均调用 `surveyService.updateSurvey` 更新 `data/status/report_status/submitter_id`。
4. 保存成功后同步本地缓存 `ems_surveys`。
5. 页面顶部的操作按钮区与报告页保持统一布局，但会按权限和表单状态控制显示。
6. 已完成表单进入只读模式，禁止继续编辑。

### UC-07 提交并生成报告

操作步骤：
1. 在填写页顶部统一操作区点击“提交并生成报告”。
2. 等待 AI 分析完成后自动跳转报告页。
3. 跳转后可通过顶部“表单 / 报告”页签在两个详情页之间来回切换。

业务流程：
1. 若存在未保存变更，先自动保存草稿。
2. 调用 `generateEnergyReport` 生成 AI 结论（无 `GEMINI_API_KEY` 时走兜底报告）。
3. 更新 `survey_forms`：
   - `status=completed`
   - `report_status=generated`
   - `data.submit_time=当前时间`
4. 调用 `buildReportBundle` 生成完整报告包（AI + 模板 + 能力匹配 + 售前联系人）。
5. 报告写入本地 `ems_reports`，跳转 `/reports/:id`。

### UC-08 报告查看、分享与导出

操作步骤：
1. 进入 `/reports/:id`。
2. 页面顶部使用与表单查看页一致的详情头部，展示项目、客户、行业、区域、生成时间与操作按钮。
3. 通过顶部“表单 / 报告”页签返回表单查看页，或停留在当前报告页。
4. 在报告内容区切换“AI诊断报告 / 模板报告”。
5. 点击“链接分享”复制报告链接。
6. 点击“导出 PDF”导出当前报告视图。

业务流程：
1. 页面从 `ems_surveys` 和 `ems_reports` 读取数据。
2. 如果历史报告结构不完整，系统自动重建并回写缓存。
3. 若售前联系人缺少手机号/邮箱，系统会补查用户信息并更新报告缓存。
4. AI 报告会额外展示：
   - 模板识别能力标签
   - 能力匹配计算规则
   - 综合解决方案清单
5. 顶部操作区在视觉结构上与表单页统一，但导出 PDF 时会自动隐藏不需要导出的操作控件。
6. 导出时通过 `html2canvas + jsPDF` 生成多页 PDF。

### UC-09 调研模板查看

操作步骤：
1. 进入 `/customer-survey/templates`。
2. 查看模板章节、字段、可见性规则。
3. 可在页面内做模板名称展示覆盖（本地存储）。

业务流程：
1. 模板来源于前端预置 `SURVEY_TEMPLATES`。
2. 名称覆盖写入 `ems_survey_template_name_overrides`，不改数据库。

### UC-10 报告模板查看

操作步骤：
1. 进入 `/product-solution/report-templates`。
2. 查看模板正文（富文本分段）与图表展示。
3. 可维护模板名称/描述的本地覆盖。

业务流程：
1. 模板来源于预置 `REPORT_TEMPLATES`。
2. 名称与描述覆盖写入本地：
   - `ems_report_template_name_overrides`
   - `ems_report_template_description_overrides`

### UC-11 产品能力维护

操作步骤：
1. 进入 `/product-solution/capabilities`。
2. 支持行内新增、编辑、删除、批量删除。
3. 支持 Excel 导出模板与数据。
4. 支持 Excel 导入，确认后“全量覆盖”当前能力清单。

业务流程：
1. 数据主存储为本地 `ems_product_capabilities`。
2. 行业/场景/能力类型选项优先读本地字典，不足时回源 `dict_types/dict_items`。
3. 导入时校验：能力名称必填、类型合法、行业/场景值必须在字典选项内、ID 不重复。
4. 导入确认后直接替换当前能力列表。

### UC-12 用户管理

操作步骤：
1. 进入 `/settings/users`。
2. 可新增/编辑用户，选择用户类型（内部/外部）和角色（可多选）。
3. 可启用/禁用账号。
4. 可重置密码。
5. 可删除用户。

业务流程：
1. 创建/编辑前调用 `validateUserRoles` 校验“用户类型与角色类型一致”。
2. 新建用户写入 `users`，并同步 `role_id` + `role_ids`。
3. 重置密码会生成一次性临时密码，并将密码摘要写入 `password_hash`。
4. 删除用户调用 `users` 表删除。

### UC-13 角色管理

操作步骤：
1. 进入 `/settings/roles`。
2. 可创建角色、编辑角色名称/类型/描述。
3. 可在权限矩阵中勾选模块动作权限。
4. 可删除角色（预置角色不可删）。

业务流程：
1. 角色存储在 `roles`，权限存储为 `permissions JSONB`。
2. 删除时会拦截预置角色（超级管理员、售前工程师、外部客户）。

### UC-14 字典管理

操作步骤：
1. 进入 `/settings/dictionaries`。
2. 左侧管理字典类型，右侧管理字典项或区域。
3. 支持新增/编辑/删除字典类型与字典项。
4. 区域支持树形层级维护。
5. 支持导出 JSON。

业务流程：
1. 优先加载数据库 `dict_types/dict_items`，失败时回退本地缓存。
2. 系统会确保行业/场景/能力类型等必需字典存在。
3. 预置受保护类型（行业/区域/能力/场景）不可删除。
4. 区域主要维护在本地缓存 `ems_regions`。

### UC-15 售前配置

操作步骤：
1. 进入 `/settings/pre-sales`。
2. 新增或编辑“售前人员 - 区域 - 行业”分配关系。
3. 支持删除分配记录。

业务流程：
1. 数据存储在本地 `ems_presales_assignments`。
2. 可选人员来自本地用户缓存，默认优先筛出售前用户。
3. 可选区域/行业来自字典与区域缓存。

### UC-16 消息中心

操作步骤：
1. 进入 `/settings/messages`。
2. 查看当前用户可见消息。
3. 可单条“标记已读”或“全部已读”。

业务流程：
1. `messageService.getCurrentUserMessages` 汇总三类消息：
   - 指定用户
   - 指定角色
   - 广播消息
2. 已读操作更新 `messages.read=true`。

### UC-17 日志管理

操作步骤：
1. 进入 `/settings/logs`。
2. 查看系统操作日志，包括操作时间、用户、类型、操作内容、结果和客户端地址标识。
3. 可按日志类型筛选：登录、调研、用户/角色、系统。

业务流程：
1. 调用 `logService.getLogs` 按时间倒序读取 `system_logs`。
2. 服务层根据 `operator_id` 补齐 `users` 表中的用户名；未登录或无法识别的记录显示为“系统/未登录用户”或“未知用户”。
3. 关键操作由服务层调用 `createAuditLog` 写入审计日志，日志写入失败不会阻断原业务操作。
4. 生产环境部署 `audit-log` Edge Function 后，日志由服务端写入，可记录真实客户端 IP、User-Agent、来源和哈希完整性信息。
5. 日志页“来源”为 `edge-function` 且“完整性”显示哈希前缀时，表示该记录已走服务端加固审计；显示 `browser-fallback` 或“未加固”时，表示仍处于兼容降级路径。

### UC-18 售前综合看板与客户需求排行

操作步骤：
1. 进入首页 `/dashboard`。
2. 在“本月 / 本年 / 累计”间切换统计范围。
3. 查看“客户需求排行”。
4. 阅读图表下方的需求识别说明与关键词示例。

业务流程：
1. 系统读取当前时间范围内的调研表单。
2. 根据表单所选模板，提取所有“已填写字段”的字段标题、章节标题、候选项和填写值。
3. 按需求识别规则识别每张表单命中的需求标签。
4. 聚合时按客户去重：同一客户跨多张表单命中同一需求，只计 1 次。
5. 最终按“命中该需求的去重客户数”倒序输出排行。

## 5. 识别与匹配规则

### 5.1 客户需求识别与排行规则

识别范围：
- 仅使用客户调研表单本身的数据，不读取 AI 报告内容。
- 同时覆盖系统预置模板和用户导入模板。

识别规则：
1. 直接关键词命中
   - 用户填写值命中需求关键词时，识别为该需求。
2. 字段语义命中
   - 字段标题或章节标题命中需求语义关键词，且该字段有填写值时，识别为该需求。
3. 选项命中
   - 单选/多选的已选项参与识别；例如选中“碳排管理”，识别为“碳管理需求”。

去重规则：
1. 单张表单内，同一需求无论命中多少次，只记 1 次。
2. 同一客户跨多张表单命中同一需求，只记 1 次。
3. 排行显示的 `count` 为去重客户数，不是表单数。

当前需求分类：
- 能效分析需求
- 数据报表需求
- 运维管理需求
- 碳管理需求
- 可视化需求
- 数据采集接入需求
- 预警监测需求
- 节能改造需求

### 5.2 报告能力匹配与综合方案输出规则

能力匹配分值规则：
1. 行业匹配：`+30`
2. 已填场景命中：`+15/项`，上限 `30`
3. 模板场景命中：`+10/项`，上限 `20`
4. 能力名称命中问卷：`+20`
5. 能力名称命中模板：`+12`
6. 模板字段语义命中：`+6/项`，上限 `18`
7. 描述关键词命中：`+4/项`，上限 `16`
8. 模板标签加分：模板侧得分 `>=18` 时再 `+10`

匹配等级：
- 高匹配：总分 `>= 60`
- 中匹配：总分 `>= 35`
- 低匹配：总分 `>= 20`
- 待确认：总分 `< 20`

报告输出内容：
1. 模板识别能力标签
   - 说明模板本身识别出的能力方向和证据。
2. 能力匹配计算规则
   - 页面直接展示当前规则和阈值。
3. 综合解决方案清单
   - 每项包含：能力名称、匹配等级、模板标签、具体功能能力、命中规则、证据、关联建议、行动建议。
4. 历史报告兼容
   - 老报告打开时若缺失这些结构，系统会自动重建。

## 6. 状态与关键字段规则

### 6.1 调研状态
- `status`：`draft` / `in_progress` / `completed`（兼容中文状态值）。
- `report_status`：`pending` / `generated`（兼容中文状态值）。

### 6.2 授权访问
- `data.external_link_enabled=true`：允许授权链接访问。
- `data.external_access_user_ids`：记录已授权外部用户 ID 列表。

### 6.3 提交时间
- 提交时写入 `data.submit_time`，列表优先从该字段显示提交时间。

## 7. 常见问题

### 7.1 登录失败
- 用户不存在。
- 账号或密码错误。
- 账号状态为禁用。

### 7.2 外部用户打不开非授权页面
- 属于权限设计：外部用户仅可访问调研列表与授权填写页面。

### 7.3 无法生成 AI 报告
- 未配置 `GEMINI_API_KEY` 时会自动使用兜底报告。
- 若页面仍无报告，请检查表单数据是否成功提交。

### 7.4 导入产品能力失败
- Excel 模板字段不完整。
- 能力类型不在“软件/硬件/咨询/改造施工”范围内。
- 行业/场景值不在字典选项中。

## 8. 数据与安全提示

- 当前版本登录态和部分业务数据保存在浏览器 `localStorage`，清缓存会影响本地显示数据。
- 重置密码使用一次性临时密码；上线环境建议迁移到标准认证体系和服务端会话。
- 建议生产环境关闭前端高权限密钥回退逻辑，并将 AI 调用迁移服务端。
